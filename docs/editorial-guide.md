# dnews 双语新闻早报编辑规范

## 1. 产品定义

每天日本时间 06:00 启动一次完整任务，制作运行当天日期的日本新闻早报。覆盖窗口固定为前一天 06:00:00 至当天 05:59:59（JST）。版次日期是出版日期，不要求所有事件都发生在当天零点以后。

每期固定 26 个新闻事件：

- `core` 8 篇：政治、经济、外交、安全、统计、重大灾害和全国性事件；
- `social` 8 篇：公共服务、医疗、家庭、劳动、教育、地方治理和生活条件；
- `other` 10 篇：科学、文化、城市、体育、电影、出版和地方社会新闻。

每个事件分别写一篇中文独立稿和一篇日语原生独立稿，共 52 篇正文；另生成两种语言的日报索引。

## 2. 正式候选池

候选池只收录已经由可信新闻媒体报道，或由权威机构正式发布的真实新闻事项。

### 2.1 新闻媒体

- NHK、共同通信、时事通信；
- 读卖、朝日、每日、日经、产经；
- TBS NEWS DIG、FNN、テレビ朝日、日テレ等主要电视新闻；
- 可信地方报纸与地方电视台；
- 必要时使用 Reuters、AP、Bloomberg、BBC、FT 等补充日本相关国际、外交和财经背景。

### 2.2 第一手来源

- 首相官邸、国会、法院、警察、消防、气象厅；
- 各省厅、日本银行、自治体；
- 医院、大学、研究机构；
- 上市公司和重要企业正式公告；
- 文化、体育、赛事和公共机构正式结果或开幕公告。

### 2.3 明确排除

以下内容不得作为候选来源或入选依据：

- X、社交媒体热词和普通用户讨论；
- Google Trends、Yahoo 搜索词；
- 新闻访问排行榜和点击量；
- 粉丝应援、抽奖、广告活动；
- 只有预告、没有当天新事实的宣传稿；
- 没有可靠来源的截图、传言和匿名转述。

社交媒体认证账号只有在它本身是政府、机构、企业或当事人的正式发布渠道时，才可作为第一手来源，而不是热度指标。

## 3. 候选发现

06:00 运行后，先检索覆盖窗口内的新闻。目标候选量为 60—120 条，不按媒体数量平均分配。

每个候选至少记录：

```yaml
headline:
published_at:
source_name:
source_url:
new_fact:
entities:
location:
initial_section:
```

候选必须包含可陈述的新事实，例如决定、结果、数据发布、事故、灾害、司法节点、停产复产、正式开幕或持续事件的新进展。

## 4. 事件聚类与去重

按事件计数，不按文章链接计数。

- 同一通讯社稿的多次转载只算一个来源；
- 同一机构公告被多家媒体改写，先合并为一个事件簇；
- 标题不同但事实主体、时间和结果相同，应合并；
- 同一重大事件可以拆成多篇，但每篇必须有不同主体、影响对象或新闻问题。

例如地震可以拆成产业供应链、避难生活、医疗调整和公共设施影响；不能把四家媒体的同一伤亡更新拆成四篇。

## 5. 26 篇选定方法

### 5.1 硬门槛

每个入选事件必须同时满足：

1. 覆盖窗口内出现明确新事实；
2. 有可访问的可信来源；
3. 能够建立独立资料包；
4. 能解释公共影响、制度意义或具有记录价值的社会现场；
5. 能写成独立新闻，而不是标题摘录或活动软文。

### 5.2 重要性排序

重要性依据：

- 对生命、安全、收入和基本生活的影响；
- 制度和政策意义；
- 经济与产业后果；
- 后果持续时间；
- 新事实强度；
- 来源可靠性与独立确认；
- 是否补足全国媒体容易忽略的地方和社会层面。

不依据社交热度、搜索量、点击量或粉丝规模。

### 5.3 兜底搜索

初选后必须主动检查政治、国会、经济、金融、劳动、统计、灾害、事故、公共安全、司法、外交、医疗、教育、地方治理、科学、文化和体育，避免只依赖首页头条。

### 5.4 安静日期

仍维持 8/8/10 和 26 篇规模，但不得用纯预告或宣传稿凑数。可扩大对地方媒体、大学研究成果、公共机构正式开幕、赛事结果、城市治理和文化公共性新闻的检索。若最终不足 26 篇可靠新闻，任务必须失败并说明缺口，不得伪造或降低来源标准。

## 6. 入选后的资料包

每个事件重新检索，不直接根据发现页面写稿。资料包应包含：

- 当天核心新事实和准确时间；
- 至少一个第一手来源；
- `core` 和 `social` 原则上至少两条可链接来源；
- `other` 至少一条权威来源，条件允许时增加独立报道；
- 关键数字与比较基准；
- 必要的制度、历史或产业背景；
- 当事者立场和明确归因；
- 尚未确认的部分；
- 下一次会议、实施、公布、审理或复产节点。

## 7. 新闻写作方法

### 7.1 标题

标题写“已确认的新事实 + 最重要的结果或影响”。不得使用夸张词、推测性因果或没有信息量的评价。

### 7.2 导语

第一段回答谁、何时、做了什么、结果是什么。第二句可解释最直接的意义。中文导语应形成完整摘要；日语导语通常为 2—3 句，不得明显缩水。

### 7.3 正文

一般顺序：

1. 当天新事实；
2. 为什么重要；
3. 时间线、数字、背景、影响和不同立场；
4. 尚未确认的内容；
5. 明确的下一节点。

分析只能解释已确认事实，不得改变事实的确定程度。

### 7.4 表述纪律

严格区分考虑、提出、宣布、决定、通过和实施；严格区分怀疑、逮捕、送检、起诉、审理和法院认定；严格区分市场推算、准备动作、实际交易和正式统计确认。

### 7.5 篇幅底线

新 schema 版次最低正文长度（不含来源）：

| 层级 | 中文 | 日语 |
|---|---:|---:|
| core | 900 个非空白字符 | 1000 个非空白字符 |
| social | 650 个非空白字符 | 750 个非空白字符 |
| other | 400 个非空白字符 | 550 个非空白字符 |

## 8. 双语关系

两种语言共享事件事实、数字、来源、slug、层级和排序，但不共享最终正文。

- 中文版面向中文读者，补足日本制度背景；
- 日语版必须重新阅读日语官方资料和日语报道后独立写作；
- 日语版不得由中文版翻译；
- 日语 front matter 必须包含 `editorial_origin: japanese-sources` 和 `translation_status: original`；
- 中日 slug 集合必须完全一致。

## 9. 元数据

每篇稿件必须包含：

- `news_date` 与 `edition_date`；
- `daily_section`；
- `slug`；
- `excerpt`；
- `categories`、`tags`；
- `article_type`、`analysis_angle`；
- `importance`；
- `seo_title`、`meta_description`；
- `source_checked_at`；
- `wordpress` 字段。

每篇 12—25 个标签，标签必须逐字出现在正文；`wordpress.categories` 和 `wordpress.tags` 必须与顶层字段完全一致。新日语版次的 `wordpress.status` 默认写 `publish`。

## 10. 发布纪律

所有内容先进入 `news/YYYY-MM-DD-morning` 独立分支。运行生成器和验证器后创建 PR。只有单元测试、版次验证、Jekyll 构建和页面验收全部通过，才允许合并 `main`。

合并后：

- GitHub Pages 部署中文版；
- WordPress 工作流只发布本次变化涉及的版次；
- WordPress 按 slug 创建或更新，默认 `publish`；
- 日语日报必须包含 26 个独立文章链接；
- 公开 URL 验证全部返回 HTTP 200 后才报告成功。
