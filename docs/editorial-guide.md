# dnews双语新闻早报编辑规范

## 1. 产品定义

每天日本时间06:00启动一次完整任务，制作运行当天日期的日本新闻早报。覆盖窗口固定为前一天06:00:00至当天05:59:59（JST）。

每个入选事件分别写一篇中文独立稿和一篇日语原生稿，并生成两种语言的日报索引。日语版不是中文版翻译。

版面采用弹性数量：

- `core`：6—8篇，政治、经济、外交、安全、统计、重大灾害和全国性事件；
- `social`：8—12篇，公共服务、医疗、家庭、劳动、教育、地方治理和生活条件；
- `other`：10—15篇，科学、文化、城市、体育、电影、出版和地方社会；
- 总计通常24—35篇。

## 2. 新闻信息来源

候选条目只从以下入口获取：

- Yahoo!ニュース主要页面；
- Google News日本头条；
- NHK NEWS WEB；
- 朝日新闻；
- 读卖新闻；
- 每日新闻；
- 日本经济新闻；
- 产经新闻；
- 共同社；
- 时事通信；
- NHK。

Yahoo!ニュース和Google News是发现入口，不是最终写作来源。写作时必须回到原媒体、正式资料和可信独立报道。

明确排除：X、社交热词、Google Trends、Yahoo搜索词、粉丝讨论、访问排行榜、点击量、广告、抽奖和没有新事实的活动预告。

## 3. 候选记录

每条候选至少记录：

```yaml
headline:
published_at:
source_name:
source_url:
source_page:
page_position:
new_fact:
entities:
location:
initial_section:
```

必须有可陈述的新事实，例如决定、结果、数据发布、事故、灾害、司法节点、停产复产、正式开幕或持续事件的新进展。

## 4. 事件聚类与重复判断

按事件计数，不按链接计数。

- 同一通讯社稿的转载只算一个来源信号；
- 同一事件的不同标题和重复更新先合并；
- 同一机构公告被多家媒体改写，合并为一个事件簇；
- 只有主体、影响对象或新闻问题明显不同，才可拆成多篇。

## 5. 重要性判断与选稿

### 5.1 主要信号

第一层判断主要依靠：

1. 事件在Yahoo!ニュース、Google News、NHK及各媒体页面中的位置；
2. 有多少家独立媒体重复报道；
3. 是否持续出现实质性更新。

页面位置是编辑信号，不是机械分数。通讯社同稿的多次转载不能虚增重复度。

### 5.2 综合判断

在主要信号基础上，再考虑：

- 公共影响范围；
- 制度与政策意义；
- 新事实强度；
- 后果持续时间；
- 来源可靠性；
- 独立确认程度；
- 生命、安全和公共服务的紧急性。

重大灾害、重大政策决定、关键经济数据、国家安全和重大司法结果具有强制优先权。

### 5.3 数量决定

每天根据真实新闻量决定三个分类的实际篇数。不得为了达到上限使用弱新闻、宣传稿或普通活动预告。只要三个分类都在允许范围内，就可以生成正式版次。

## 6. 入选后的资料包

每个事件必须重新检索，不得直接根据聚合页摘要写稿。资料包至少包括：

- 当天核心新事实和准确时间；
- 原报道；
- 第一手正式资料；
- 必要的独立报道；
- 关键数字与比较基准；
- 制度、历史或产业背景；
- 当事者立场和明确归因；
- 尚未确认的部分；
- 下一次会议、实施、公布、审理或恢复节点。

`core`和`social`原则上至少两条可链接来源；`other`至少一条权威来源，条件允许时增加独立报道。

## 7. 统一新闻写作方法

三个分类投入相同的检索、核验和编辑努力，区别只在叙事方式。

### 7.1 标题

标题写“已确认的新事实＋最重要的结果或影响”。不得使用夸张词、推测性因果或没有信息量的“引发关注”。

### 7.2 导语

第一段回答谁、何时、做了什么、结果是什么。第二句可解释最直接的意义。中文导语应形成完整摘要；日语导语通常为2—3句，不得明显缩水。

### 7.3 正文结构

一般顺序：

1. 当天新事实；
2. 为什么重要；
3. 时间线、数字、背景、影响和不同立场；
4. 尚未确认的内容；
5. 明确的下一节点。

### 7.4 分类写法

- `core`：强调决定、制度、数字、责任主体和后果；
- `social`：从具体新闻事实解释公共服务、劳动、家庭、医疗、教育和地方生活，不写成泛泛评论；
- `other`：可以增加现场感、知识性或文化背景，但仍须是完整新闻，不得写成宣传稿、活动预告或简单摘要。

### 7.5 表述纪律

严格区分考虑、提出、宣布、决定、通过和实施；严格区分怀疑、逮捕、送检、起诉、审理和法院认定；严格区分市场推算、准备动作、实际交易和正式统计确认。

### 7.6 篇幅底线

| 分类 | 中文 | 日语 |
|---|---:|---:|
| core | 900个非空白字符 | 1000个非空白字符 |
| social | 650个非空白字符 | 750个非空白字符 |
| other | 400个非空白字符 | 550个非空白字符 |

## 8. 双语关系

两种语言共享事件事实、数字、来源、slug、分类和排序，但不共享最终正文。

- 中文版面向中文读者补足日本制度背景；
- 日语版必须重新阅读日语正式资料和日语报道后独立写作；
- 日语版不得由中文版翻译；
- 中日slug集合必须完全一致。

## 9. 元数据与版次

每篇稿件必须包含：

- `news_date`与`edition_date`；
- `daily_section`；
- `slug`；
- `excerpt`；
- `categories`、`tags`；
- `article_type`、`analysis_angle`；
- `importance`；
- `seo_title`、`meta_description`；
- `source_checked_at`；
- `wordpress`字段。

新弹性版次使用manifest schema version 3。manifest中的`expected_counts`记录当期实际篇数，`count_ranges`记录允许范围。历史schema version 1和2继续按原有8/8/10验证。

## 10. 发布纪律

所有内容先进入`news/YYYY-MM-DD-morning`独立分支。生成器建立manifest和两种日报，验证器检查实际数量、中日slug、来源、篇幅、标签和元数据。

只有单元测试、版次验证、Jekyll构建和页面验收全部通过，才允许合并`main`。

合并后：

- 中文版增加到GitHub Pages；
- 日语版增加到shinkiji；
- WordPress按slug创建或更新；
- 历史日期的文章和日报保留；
- 当天重跑只更新同日期、同slug内容；
- 公开URL验证完成后才报告成功。
