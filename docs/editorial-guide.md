# dnews 再报道编辑规范

## 1. 发现与入选

1. 从 Yahoo!ニュース、Google News、NHK、全国报纸、通讯社、电视新闻、地方媒体和官方发布建立候选池。
2. 按事件聚类；同一通讯社稿的多次转载只算一个报道源。
3. 每天选择 8—12 个具有明确新事实的事件。
4. 重要性主要由公共影响、制度意义、后果、持续性和独立确认决定，热度只作辅助。

## 2. 入选后的重新检索

每个事件重新建立资料包：

- 核心新事实及发生时间
- 第一手资料
- 两家以上独立报道（条件允许时）
- 关键数字及比较基准
- 必要的历史、制度和产业背景
- 当事者立场及明确归因
- 尚未确认之处
- 下一时间节点

## 3. 文章类型

- **事实报道型**：决定、结果、事故和即时事实。
- **解释型**：制度、政策、统计和技术背景。
- **分析型**：政治、外交、产业与多方利益。
- **续报型**：持续事件在当天出现的新进展。
- **社会文化型**：人物、作品和社会现象的公共意义。

## 4. 基本结构

公开稿采用弹性结构，但一般包括：

1. 事实型标题
2. 交代当天新事实与结果的导语
3. 说明为何重要的意义段
4. 事件经过、背景、数字、影响、分歧等必要模块
5. 具体的下一节点或由事实导出的未决问题
6. 资料来源

分析不是固定配额。灾害和初报可以几乎不加评论；政策、经济与外交稿可加入适度结构性分析。任何分析都不得改写事实的确定程度。

## 5. 表述纪律

严格区分“考虑、提出、宣布、决定、通过、实施”；严格区分警方怀疑、检方起诉和法院认定。尚未确认的市场行动和匿名消息不得写成确定事实。标题和导语不使用无法核验的内容。

避免“引发关注”“值得关注”“未来可期”等没有具体信息的句子。结尾应写明下一次会议、实施日期、数据发布、审理节点或仍待解决的明确问题。

## 6. 发布元数据

每篇 Markdown front matter 同时保存：

- permalink / slug
- excerpt
- categories / tags
- article_type / analysis_angle
- importance
- seo_title / meta_description
- wordpress 映射字段
- source_checked_at

这些字段用于 GitHub Pages、WordPress 及后续编辑系统，原则上不在公开正文中显示。
